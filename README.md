# irAE-Map

**Status:** released v1.0.0 (2026-10-13) | **Maintainer:** Onyekachi Innocent Ike-Okpe, [ORCID 0000-0001-7234-7474](https://orcid.org/0000-0001-7234-7474) | **License:** table and documents CC BY 4.0, code MIT

**In plain terms:** Immunotherapy drugs can make the immune system attack healthy organs. The same side effect is written down three different ways: cancer trials use CTCAE terms, hospitals use ICD-10-CM codes, and the FDA's safety database uses MedDRA reaction terms. irAE-Map is a free, clinician-checked table that links all three for each kind of immunotherapy side effect, with a reason, a confidence rating, and the diagnoses most often confused with it.

New here? Read [docs/START_HERE.md](docs/START_HERE.md) first. Unfamiliar terms are explained in [docs/GLOSSARY.md](docs/GLOSSARY.md).

irAE-Map is a versioned crosswalk from immune-related adverse event (irAE) categories of immune checkpoint inhibitor (ICI) therapy to (1) CTCAE v6.0 terms with their grade definitions, (2) ICD-10-CM FY2027 codes, including the drug-cause companion codes T45.AX5- and T45.1X5-, and (3) MedDRA preferred terms as reported in FAERS, with report counts from openFDA. Each mapping carries a role (primary, supporting, look-alike, companion), a confidence rating, and a clinical rationale. Candidates and draft rationales were generated by documented rules from the public sources; the author's decisions on them are recorded per row. It is intended for EHR phenotyping, claims and registry studies, pharmacovigilance queries, and harmonizing trial and real-world irAE definitions.

## What is here

```
code/        numbered scripts in run order, plus the category rules (categories.py)
data/raw/    inputs as downloaded, with PROVENANCE.txt (URL, date, size, SHA-256)
data/curation/  every candidate considered, and the review workbook with the author's decisions
data/processed/ the released table, the ICD-10-CM expansion, categories, qa_report.txt, stats.json
docs/        START_HERE, GLOSSARY, BUILD_SPEC, CODEBOOK, LIMITATIONS, VERIFY_CHECKLIST, NEXT_STEPS
report/      mapping rationale document (built from stats.json)
```

## Run it

```
pip install -r requirements.txt
python code/01_fetch.py          # downloads sources (skips files already present)
python code/02_candidates.py     # proposes candidates; rebuilds the review workbook, keeping decisions
python code/03_build.py          # builds the table from the decisions, with QA
npm install && node code/04_document.js   # builds the mapping rationale document
python code/05_coverage.py       # coverage analysis: CTCAE terms without a specific ICD-10-CM code
```

Optional: set `OPENFDA_API_KEY` (free, https://open.fda.gov/apis/authentication/) before step 1 to raise openFDA's per-query term limit from 100 to 1,000.

A stranger should be able to run these from this README alone and reproduce `data/processed/` exactly, given the same raw files (checksums in `data/raw/PROVENANCE.txt`). openFDA is updated over time, so a fresh download will change FAERS counts; the committed raw files reproduce the released numbers.

## Headline numbers

Version 1.0.0 links 36 irAE categories through 918 mappings: 137 to CTCAE v6.0 terms (29 of the 134 distinct terms are new in v6.0), 384 to ICD-10-CM code families covering 1,939 billable codes, and 397 to FAERS reaction terms, drawn from 290,091 FAERS reports naming a checkpoint inhibitor. All numbers come from `data/processed/stats.json`; build checks are in `data/processed/qa_report.txt`.

## Using the table

See the worked example at the end of [docs/CODEBOOK.md](docs/CODEBOOK.md). In short: use `data/processed/irae_map_icd10cm_expanded.csv` to join to diagnosis tables; require a companion code (category `ALL`) for attribution to an ICI; exclude look-alikes; choose a confidence threshold.

## Limitations

Read [docs/LIMITATIONS.md](docs/LIMITATIONS.md) before using or citing anything here. The most important: a code is not a validated irAE diagnosis, the drug-cause code changed on 2024-10-01, and FAERS counts are reports, not incidence.

## How it was made

Claude (Anthropic) wrote the code, the candidate search rules and the draft suggestions under the author's direction. The author, a physician, decided the mappings: in v1.0 by accepting the drafted suggestions as a group and setting individual rows where needed (see `data/curation/DECISION_LOG.md`). Each released row records which (`decision_type`). Rows with no drafted suggestion are not released.
